# Data Model: Review Artefacts

No application data model change. Artefacts of the review:

## Finding (in `security/REPORT.md`)

| Field | Values |
|---|---|
| id | `F-###` |
| category | A01 … A10 (2025) |
| component | backend / frontend / ocr-service / chart / compose / ci / scripts / images |
| severity | critical / high / medium / low / informational |
| status | suspected / confirmed / fixed / tracked / accepted |
| location | `path:line` |
| description, impact, likelihood | text |
| reproduction | experiment ID or steps |
| evidence | test output summary (no secrets/real data) |
| recommendation / fix | text, commit/PR when fixed |

## Experiment (in `security/experiments/`, catalogue in `contracts/`)

| Field | Meaning |
|---|---|
| id | `E-A01-001` … |
| category, goal | OWASP category, what is attacked |
| setup, steps | rig state and requests |
| expected | secure behavior |
| repeat, failure rate | races: ≥ 100 repetitions, reported failures |
| mutant | weakened variant that must make it fail (if applicable) |

## Coverage matrix

Rows = components, columns = A01…A10; each cell lists methods (read / tool / experiment IDs) and the result (`no finding`, or finding IDs).

## Synthetic data (rig)

Users (superadmin, admin, manager, user A, user B, user without group), two properties with disjoint access, meters, readings, small generated test images; all generated by `seed.py`, deleted with the rig.
