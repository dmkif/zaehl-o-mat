# Triage group 3: test_a08_integrity (10) and test_uploads (5)

Source: `security/rig/.last-logs/full-run-1.log`, tests in `security/experiments/`, backend read-only. Rig not started.
Result: 15 failures = **15 REAL**, **0 pure TEST/RIG bugs**. Two tests also carry a small test-robustness defect (noted below) that does not change the verdict.

## Root causes

1. **OCR-service response is used unvalidated** (`backend/app/services/ocr_pipeline.py:416-423`): `resp.json()` is not guarded (`JSONDecodeError`/`RecursionError` are not `httpx.HTTPError`, so `routers/ocr.py:172/190` do not catch them -> 500), and `body.get(...)` is returned with any type and size. Candidate B-25 (passthrough) and B-28 (output unconstrained). The 500s are an A10 aspect of the same lines, not yet worded in B-25.
2. **LLM reading is cleaned but not length-bounded** (`ocr_pipeline.py:191-221`: `re.sub(r"[^\d.,]","",v)` keeps 5 M digits; `_clean_serial_value` `:245-250` has no charset/length cap). B-28 names only the serial, the reading is the same gap.
3. **Scan stores the file before any content check and never cleans up** (`routers/ocr.py:281-329`, bulk `:ocr.py` generate(): `write_bytes` before OCR). Only `filetype.guess_mime` (magic bytes) is checked; no `Image.open().verify()`, no pixel cap. Candidate B-10 (decode/pixel cap), B-24 (disk fill), partial-write note in the A10 section.
4. **`image_path` on reading create is trusted** (`routers/readings.py:67-94`, `routers/uploads.py:37-52`). Candidate B-07.
